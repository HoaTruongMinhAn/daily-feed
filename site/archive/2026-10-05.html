- Model bị xóa qua asset service của Apple; System Integrity Protection vẫn bật, không sửa file dưới /System.
- Profile chuyển hướng việc tải model tới một cổng local đóng để macOS không tải lại.
- Công cụ không gửi request mạng và không thu thập dữ liệu.

Với codex-rs, clean build nhanh hơn 37%. Trên 4 core, mức tăng nhỏ hơn: check của rust-analyzer nhanh hơn 24%, build 13-15%.

- Golden set: file JSON/JSONL cạnh prompt, khởi đầu khoảng một chục case, thêm một dòng cho mỗi bug production. Ưu tiên case thật (tin nhắn rỗng, tiếng Ả Rập, chỉ có mã đơn, prompt injection). Để prompt trong file riêng để thay đổi prompt và kết quả eval nằm cùng diff.
- Assertion tất định (Zod schema, chuỗi bắt buộc hoặc cấm, khoảng số) bắt phần lớn regression, chạy mili giây và không tốn tiền; chạy trước judge.

Mutation testing: tool cố ý cài lỗi nhỏ vào production code (ví dụ đảo điều kiện) rồi chạy lại test. Test fail thì mutation bị "killed"; test vẫn xanh thì mutation "survived", nghĩa là test yếu. Tỷ lệ mutation bị killed là mutation coverage. Quy trình hai pha:
- Chạy toàn bộ test, ghi lại test nào phủ dòng production code nào.
- Mutate code, chỉ chạy lại các test phủ dòng đã đổi, rồi đánh giá killed hay survived.

Một test xanh ở đây là kết quả xấu. Julius Mischok (dùng mutation testing trong Java): "Wenn diese Tests danach immer noch grün sind, ist es schlecht." Ông cho rằng khái niệm và công nghệ đã có gần 20 năm.

Các mutator tiêu biểu: dịch biên (> thành >=), đảo so sánh (> thành <), phủ định bằng (== thành !=), phủ định điều kiện (if (x) thành if (!x)), lật boolean, và trả về giá trị mặc định (0, false, list hoặc set rỗng). Mutator giá trị mặc định giả vờ method không làm gì; nếu không test nào phát hiện thì không ai kiểm tra kết quả của method. Mutator về biên khớp với boundary value analysis; mutation sống sót thường do thiếu dữ liệu test đúng tại biên.

Yêu cầu: test phải độc lập và ổn định vì tool chạy chúng lặp lại theo thứ tự bất kỳ, chỉ cần phụ thuộc giữa các test là quy trình hỏng. Khi agent viết unit test, nên chạy scheduled job hàng tuần hoặc vào cuối sprint để xem test sinh ra có thật sự bắt lỗi không.

Một test xanh ở đây là kết quả xấu. Julius Mischok (dùng mutation testing trong Java): "Wenn diese Tests danach immer noch grün sind, ist es schlecht." Ông cho rằng khái niệm và công nghệ đã có gần 20 năm.

Các mutator tiêu biểu: dịch biên (> thành >=), đảo so sánh (> thành <), phủ định bằng (== thành !=), phủ định điều kiện (if (x) thành if (!x)), lật boolean, và trả về giá trị mặc định (0, false, list hoặc set rỗng). Mutator giá trị mặc định giả vờ method không làm gì; nếu không test nào phát hiện thì không ai kiểm tra kết quả của method. Mutator về biên khớp với boundary value analysis; mutation sống sót thường do thiếu dữ liệu test đúng tại biên.

Yêu cầu: test phải độc lập và ổn định vì tool chạy chúng lặp lại theo thứ tự bất kỳ, chỉ cần phụ thuộc giữa các test là quy trình hỏng. Khi agent viết unit test, nên chạy scheduled job hàng tuần hoặc vào cuối sprint để xem test sinh ra có thật sự bắt lỗi không.
